# 3. Zeabur 平台入侵

**来源：** [sorrycc 2026-10 梳理 §3](https://research.sorrycc.dev/@sorrycc/2026-10-security-incidents)  
**可信度：** 已确认（Zeabur 10-19 初步调查报告、10-20 官方推文、10-17 停运公告）

## 概况

攻击者利用私有配置仓库中的**明文凭据**进入共享集群、独立服务器与内部系统，并读取平台数据库。Zeabur 于 **10-17** 宣布停止运营；安全事件是公告四项原因之一（另：增长瓶颈、早期架构负担、投入评估）。

## 根因

- 私有配置仓存有明文 AWS Key 与集群管理令牌（**2024 年创建，从不过期**），管理接口暴露公网。
- 如何取得该仓库**尚未确认**。主要假设是 8 月事件泄露的 GitHub App 私钥；报告写明「目前没有证据直接证明」；已向 GitHub Support 调取记录，报告发布时尚未回复。
- 8 月后只轮换确认泄露的密钥，未处理这些明文凭据；GCP root 密码问题 9-3 已发现但未修。

## 已确认影响

| 项 | 数量 / 说明 |
| --- | --- |
| 环境变量记录 | 约 **320 万** |
| 账号记录 | **321,810**（邮箱、用户名、电话） |
| zSend API Key | **566** 个明文 |
| Access Token | **11,536** 个哈希后 |
| 客户 DB 备份 | 1 个经预签名 URL 被下载 |
| DB 服务容器被执行命令 | **865** |
| GCP 独立服务器 root 登录 | **101**；其中 **50** 植入攻击者 SSH Key |
| n8n | **607** 中 **602** 的加密密钥在环境变量中 → 其中第三方凭据应视为全部暴露 |

## 尚未确认（原文）

- 数据库实际外传量：审计只记命令不记输出；应按「每被触及库可能被读走前 5 万行/表」评估。
- tpe1、hkg1 用户 DB 备份被列出，是否下载无法确认 → 按已泄露处理。
- Hetzner（359）/ DigitalOcean（48）管理令牌 10-16 01:09 UTC 吊销；审计能力有限。
- 10-16 某 OpenAI Key 约 1,107 次调用是否相关。

## 处置与停运（原文要点）

- 轮换存放在 Zeabur 的全部密码 / API Key / 密钥（即使 8 月后已轮换）。
- DB 内部账号密码需单独改；n8n 换加密密钥并重建第三方凭据；new-api / one-api 吊销上游 AI Key。
- PostgreSQL：查陌生 role/函数/触发器/定时任务/扩展；无法确认则重建仅导入数据。
- 查 GitHub 审计：Zeabur GitHub App 在 10-15 15:05–18:54 UTC 活动。
- 账单自 10-14；GCP 独立服务器自 9-1，查 `@zeabur-pentest` SSH Key，干净环境重建。
- 8 月后已迁出自有服务器的项目，不受本次平台 DB 读取影响。
- **停运：** 10-17 停售；12-01 起独立服务器按到期关闭、共享集群暂停；12-31 全部停止（不保证都能撑到该日）。
